# v0.1.0 Release Design

## Goal

Publish the merged Loop Designing public beta as an immutable, verifiable `v0.1.0` GitHub Release.

## Distribution contract

- `VERSION` remains `0.1.0`.
- The README install command clones the immutable `v0.1.0` tag rather than the hardening branch or mutable `main`.
- The standalone distributable is `loop-designing/`; root files remain repository and contributor material.
- The release attaches `loop-designing-v0.1.0.zip`, whose archive root is `loop-designing/`, plus a published SHA-256 checksum.
- The release stays labeled public beta and preserves the Node.js 18+ requirement.

## Publication sequence

1. Merge the README install correction into `main` through a checked pull request.
2. Verify the merged commit with the syntax, harness, release-regression, validator, clean-install, and Node 18/22/24 CI gates.
3. Fast-forward the clean local `main` checkout to the verified remote commit.
4. Build the ZIP from a clean archive of that exact `main` commit and verify its contents in a separate extraction directory.
5. Create and push annotated tag `v0.1.0` at that commit.
6. Create a non-prerelease GitHub Release titled `Loop Designing v0.1.0 (Public Beta)` and attach the verified ZIP.
7. Confirm the tag, release target, asset digest, default branch, and post-release repository cleanliness.

## Failure handling

- Do not tag if the documentation PR or any verification fails.
- Do not create the GitHub Release if the tag target differs from the verified package commit.
- Do not overwrite an existing tag or release; stop if either already exists.
- Do not publish a ZIP containing repository-level tooling, Git data, symlinks, or files outside `loop-designing/`.
